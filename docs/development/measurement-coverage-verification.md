## What changed

- `model/coverage.ts` derives display facts from the current accepted draft and its existing engine
  validation report. It indexes nodes, structural leaves, distinct known measurement pairs and
  issue targets once per draft snapshot; selection, collapse and paging do not rebuild it.
- Zero and qualitative labels count as entered. Duplicate measurement rows contribute one known
  pair; orphan and branch references contribute none. Presence and cell-specific issues are
  independent. Identical repeated engine issues are linked once, without changing the report.
- Canvas shows total entered/missing/attention counts, including collapsed branches. Empty models
  say “Add alternatives/criteria · 0 expected cells”. Setup and preference issue links are separate.
  Criterion-level engine errors link to setup without becoming cell-validation claims.
- Cells reuse Measurements and Inspector. A missing scale/function leads to setup; a scale that is
  present but invalid still exposes the existing input and linked model issues. There is no second
  editor. Accepted edits continue through `store.apply` and existing operations/history.
- Stable IDs retain selection through renames. Removing either ID or making a leaf a branch clears
  cell selection on the accepted revision; undo does not resurrect it. Return to coverage and the
  Model tab restore the cell and its pages. Delayed setup/input focus waits for enabled controls
  and does not override a subsequent user focus choice.
- Both coverage and the existing measurement destination page at 20 alternatives × 20 criteria.
  Arrows cross pages; Home/End reach first/last criteria. One cell is in the tab sequence. Table
  headers show names and IDs, status uses text, scrolling is labelled, and reduced motion is honoured.
- “Evidence provenance not recorded” is explicit. Entered is neither confidence nor evidence
  verification. No numerical result is derived in TypeScript.

## Regression coverage

- Coverage model tests: zero/labels, collapsed leaves, duplicate/orphan/branch references, empty
  models, separate issue dimensions, missing with setup, selection reconciliation, page boundaries
  and pair-key collisions. Repeated identical scenario-validation issues are deduplicated for links.
- Matrix/editor component tests: visible status text and linked engine issues, every measurement
  destination, setup, focus return, keyboard crossing pages, return to selected pages, rename and
  removal/conversion/undo reconciliation. Unrelated deletions can move selection across page
  boundaries. API spies prove no edit/save/evaluation/analysis-record request from navigation.
- Real-backend browser cases: missing → zero with undo/redo; collapse-independent totals and pointer
  destinations; keyboard/issue/setup/focus routes; byte/fingerprint/history identity under navigation;
  large pages, final-cell reachability, bounded inputs and timing fixtures; reduced motion, narrow
  layout and 200% zoom screenshots.
- `COVERAGE_FRONTEND`: zero treated as missing; descendants beneath collapsed branches omitted;
  an empty model called complete; duplicate/orphan rows inflating counts. Existing mutants,
  including `RETRY_FRONTEND`, are retained unchanged.

The collapsed-branch browser case caught pointer focus revealing ancestors between pointer-down
and click, moving the matrix and losing the click. Pointer selection now occurs on click; keyboard
focus still selects immediately. Component tests caught stale setup focus stealing the return
focus and an old measurement target stealing focus after a different input was edited. Both focus
requests are now consumed, rather than replayed after every edit or remount.

## Deviations and limits

- Paging is also applied to the existing measurement editor destination, so opening a coverage
  cell cannot instantiate 10,000 inputs. It reuses the same indexes, operations and commit controls.
- The matrix is below the existing diagram and Inspector, as the design sketch permits. The
  diagram's alternatives column highlights the selected alternative; it retains its existing edit
  shortcut. Presentation remains the existing read-only tree discussion view.
- Models beyond the measured 100 alternatives / 100 leaves / 1,000 nodes keep paged forms and total
  counts, with an explicit display-performance caveat. These are measured bounds, not editor limits.
- No human usability checkpoint or screen-reader walkthrough was performed. Automated keyboard
  checks and screenshots do not establish those results. A person must still run the fresh-user
  checkpoint.
- No hosted CI ran; nothing was pushed. Installed-wheel/pipx smoke was not rerun: packaging is
  unchanged, but bundled frontend assets have changed.

## Follow-up: hosted CI, 28 October 2026

The first hosted Linux run after this development (run 40478371140, commit `eeb6935`) failed one
browser test, `visible-model.spec.ts` "keyboard, external reveal and preview request isolation",
with 2 value-function preview requests where 1 was expected. Its Playwright trace shows the first
request was sent *before* Market Size was clicked, while the test moved focus with ArrowRight and

leaf exceeded the 120 ms preview debounce, so that leaf requested its own preview. Locally the
same test passed 15 of 15 runs; holding focus for 400 ms reproduces the CI failure exactly.

The test now counts only preview requests for the criterion under test, which is what it is meant
to prove: once Market Size is selected, presentation changes never re-request its preview. Product
behaviour is unchanged. After the change: frontend check 313 passed, browser suite 81 passed, and
the isolation test 5 of 5 repeated runs. Hosted run 40652287706 (commit `508f49b`) passed: browser
suite 81 of 81.
